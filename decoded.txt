# Unify Zalo Inbound/Outbound Flow Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [] `) syntax for tracking.

**Goal:** Close the loop between Zalo message reception -> DB -> UI display, and UI message send -> Zalo delivery in demo mode.

**Architecture:** The inbound path (Zalo polling -> IngestAsync -> DB -> API -> Frontend) works. The outbound path (Frontend -> InboxEndpoints.SendOutboundAsync -> PancakeChannelAdapter.SendAsync -> Pancake API -> Zalo) is broken because PancakeConfigResolver cannot find demo tokens (stored in env vars / DemoRuntimeConfigStore) and PancakeChannelAdapter.SendAsync cannot resolve the page ID from a flat external thread ID. Fix: add env-var fallback in config resolver, add PageId to runtime config, and fall back to config page ID when SplitThread yields empty page part.

**Tech Stack:** .NET 8, EF Core + SQL Server, React 19 + TypeScript + Tailwind + TanStack Query + Axios, SignalR, Pancake Public API V2 (poll) / V1 (send).
